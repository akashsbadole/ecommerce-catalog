# Edit Product Popup Not Properly Showing

## Problem Analysis

The Edit Product popup (Dialog) in `src/components/admin/AdminProducts.tsx` has layout issues that prevent it from displaying properly. After analyzing the code:

### Issue 1: ScrollArea Structure Problem (Lines 1066-1555)
The `ScrollArea` component from Radix UI is being used incorrectly inside `DialogContent`. The problem:

1. **Radix ScrollArea expects children to render inside its internal Viewport**, but the current structure wraps the entire conditional tab content inside ScrollArea
2. **Missing parent flex layout**: `DialogContent` doesn't have proper flex layout to constrain the ScrollArea height
3. **The Variants and Related tabs content** (lines 1492-1554) is rendered AFTER the ScrollArea closes, but they should ALSO be inside the ScrollArea since they're tab content

### Issue 2: Inconsistent with other dialogs
Comparing with `AdminCategories.tsx` (line 498), other dialogs use simpler approach:
```tsx
<div className="grid gap-4 py-4 max-h-[calc(90vh-140px)] overflow-y-auto">
```
Instead of the Radix ScrollArea which has different behavior.

### Issue 3: Missing closing tag
The `</div>` at line 1490 closes the general tab content, but the Variants and Related tab content (lines 1492-1554) is OUTSIDE the ScrollArea, meaning those tabs won't be scrollable when they have overflow.

## Solution

Replace the Radix UI `ScrollArea` with a simpler native scroll approach that works better with DialogContent:

### Changes to `src/components/admin/AdminProducts.tsx`:

1. **Remove ScrollArea wrapper** (lines 1066-1555)
2. **Add `overflow-y-auto` to the dialog content container** with proper max-height
3. **Fix the structure** so all tab panels (general, variants, related) are scrollable within the same container

The fix involves:
- Removing `<ScrollArea>` wrapper
- Adding `className="max-h-[calc(90vh-140px)] overflow-y-auto"` directly to the content wrapper divs
- Ensuring all tab content uses consistent scroll behavior

This matches the pattern used in `AdminCategories.tsx` line 498, which works correctly.
